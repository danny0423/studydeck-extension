# 上架與自動發布

做完一次「一、第一次設定」之後，每次發新版只要做「二、之後每次發新版」。

## 一、第一次設定（只做一次）

除了第 2 步，全部在 Windows 的瀏覽器裡做。

| # | 做什麼 | 在哪裡 | 拿到什麼 |
| --- | --- | --- | --- |
| 1 | 開發者帳號：Google 帳號先開兩步驟驗證，付 5 美元註冊，身分選「非商家」 | https://chrome.google.com/webstore/devconsole | 開發者帳號 |
| 2 | 打包第一版：在這台跑 `python3 scripts/pack.py`，再用 VS Code 對 `dist/` 裡的 zip 按右鍵 → Download | 這台 Ubuntu | `studydeck-extension-1.0.0.zip` |
| 3 | 截一張圖：先在 Windows Chrome 裝好試用，截一張圖，傳到這台後跑 `python3 scripts/fit_screenshot.py 截圖.png` | Windows＋這台 | `store-assets/screenshot-1280x800.png` |
| 4 | 新增項目 → 上傳 zip → 照 [商店說明草稿.md](商店說明草稿.md) 填好商店資訊、隱私權、發布（選不公開）→ 送審 | 開發者後台 | 第一次審核 |
| 5 | 在 Google Cloud 建一個專案 → 搜尋並啟用「Chrome Web Store API」 | https://console.cloud.google.com | 專案 |
| 6 | 建一個服務帳戶（不用給任何角色）→ 點進去 →「金鑰」→ 新增 JSON 金鑰，會下載一個 .json 檔 | https://console.cloud.google.com/iam-admin/serviceaccounts | 服務帳戶 email、JSON 金鑰檔 |
| 7 | 開發者後台的「帳戶（Account）」→ 加入第 6 步的服務帳戶 email | 開發者後台 | 服務帳戶可以替你上傳 |
| 8 | 抄下兩個 ID：發布者 ID（後台「發布者 → 設定」）、extension ID（項目的「套件」分頁，32 個英文字母） | 開發者後台 | 2 個 ID |
| 9 | 在 GitHub repo 的 Settings → Secrets and variables → Actions，新增 3 個 secret（見下表） | GitHub | 自動發布設定完成 |
| 10 | **刪掉第 6 步下載的 .json 金鑰檔**（已經存在 GitHub secret 裡了，留在電腦上有外洩風險） | Windows | — |

### GitHub secret

| 名稱 | 值 |
| --- | --- |
| `CWS_SERVICE_ACCOUNT_KEY` | 第 6 步 .json 檔的**整個內容**（用記事本打開，全選複製） |
| `CWS_PUBLISHER_ID` | 第 8 步的發布者 ID |
| `CWS_EXTENSION_ID` | 第 8 步的 extension ID |

⚠️ 第一版（第 4 步）**審核通過**之後，才能開始用自動發布。

## 二、之後每次發新版

在這台跑：

```bash
cd /home/user/0409/studydeck-extension
# 1. 改程式
# 2. 改 src/manifest.json 的 version，例如 1.0.0 → 1.0.1（版本號沒變，商店不收）
git add -A
git commit -m "說明這次改了什麼"
git tag v1.0.1                 # 標籤一定要跟 manifest 的版本一樣，前面加 v
git push && git push origin v1.0.1
```

推上標籤後，GitHub Actions 會自動：檢查版本號 → 打包 → 上傳 → 送審。
審過之後，裝了這個 extension 的 Chrome 會在幾個小時內自己更新。

## 出問題時

| 狀況 | 去哪看 |
| --- | --- |
| 自動發布失敗 | GitHub repo 的 Actions 分頁，點失敗的那次看紅字 |
| 「標籤跟版本不一樣」 | `src/manifest.json` 的 version 跟 `git tag` 要一致 |
| 上傳回 403 | 服務帳戶 email 沒加到開發者後台（第 7 步），或 secret 貼錯 |
| 送審被退 | 開發者後台會寫原因；常見是權限理由不清楚、截圖或說明不夠 |
| 改過公開程度後，API 發布失敗 | 官方規定：手動改了公開程度，要先在後台手動發布一次，API 才能再用 |
