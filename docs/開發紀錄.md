## 二、架構

| 檔案 | 做什麼 |
| --- | --- |
| `src/manifest.json` | 名稱、版本、權限 |
| `src/background.js` | 右鍵選單 → 抓字 → 查意思 → 存待學習 → 通知 |
| `src/grab.js`＋`src/sentence.js` | 注入網頁執行：抓選的字和那一句 |
| `src/lang.js` | 猜語言（有假名→日文） |
| `src/api.js` | 呼叫 StudyDeck API |
| `src/settings.js` | 讀寫網址、登入憑證 |
| `src/options.*` | 設定頁：填網址、登入 |
| `src/popup.*` | 點圖示：登入狀態、最近 10 個待學習 |
| `scripts/pack.py` | 打包 zip（`manifest.json` 在最外層） |
| `scripts/publish.mjs` | 上傳並送審 |
| `scripts/make_assets.py` | 圖示、宣傳圖 |
| `scripts/fit_screenshot.py` | 截圖轉成 1280×800 |

## 三、決策紀錄

| 決定 | 選項 | 選了 | 理由 |
| --- | --- | --- | --- |
| 單字存到哪 | 新 API／現有「待學習」 | 現有待學習 | 後端不用改；之後在網站勾選做成學習集 |
| 意思從哪來 | 自己打／呼叫網站的單字解析 | 單字解析 | 跟網站「加入待學習」的填法一樣（`quizlet/frontend/src/components/ExplainHost.jsx:340`）；代價是沒查過的字會用 StudyDeck 的 AI 次數 |
| 怎麼觸發 | 右鍵選單／選字旁浮動按鈕 | 右鍵選單 | 不用在每個網頁常駐程式，權限最小（`activeTab`） |
| 怎麼避開 CORS | 後端加 CORS／背景程式加主機權限 | 主機權限 | 後端不用改 |
| 主機權限範圍 | 寫死 StudyDeck 網址／選用權限、登入時才要 | 選用，登入時只要那一個網址 | 網址不寫死在公開程式碼裡 |
| 放哪 | 放進 quizlet repo／獨立 repo | 獨立 repo | quizlet push 到 master 會自動部署網站 |
| 發布方式 | 自己用 git pull／上架商店＋自動發布 | 上架＋自動發布 | 使用者選擇（2026-11-26） |
| 商店 API 登入 | OAuth refresh token／服務帳戶 | 服務帳戶 | OAuth 在「測試中」狀態 refresh token 7 天過期 |
| repo 公開程度 | private／public | public | 隱私權政策網址要公開；程式碼已確認沒有私人資訊 |
| 商店公開程度 | 公開／不公開 | 不公開（拿到連結才能裝） | 只有 StudyDeck 帳號的人用得到 |

## 五、踩過的坑

| 坑 | 會怎樣 | 解法 | 依據 |
| --- | --- | --- | --- |
| 注入網頁的檔案最外層用 `const` | 同一頁第二次注入會報「已經宣告過」 | 最外層只放 `function`，其他包在立即執行函式裡 | `src/sentence.js:1`、`src/grab.js:4` |
| 日文網頁有注音（`<rt>`） | 「食べる」被抓成「食たべる」 | 抓文字時跳過 `rt`、`rp` | `src/grab.js:7` |
| 要主機權限前先 `await` 別的 | Chrome 說不是使用者操作，不給問 | 按下按鈕當下馬上呼叫 `permissions.request` | `src/options.js:31` |
| 擴充功能頁面直接寫 `<script>` 程式碼 | 被 Chrome 擋 | 一律放在另外的 `.js` 檔 | `src/popup.html` |
| 商店 API 不能建立新項目 | 自動發布第一次一定失敗 | 第一版手動上傳、審過後才用 API | 官方文件 using-api |
| 在後台手動改公開程度 | API 發布失敗 | 改完要先手動發布一次 | 官方文件 using-api |
| 標籤跟 manifest 版本不一樣 | 上傳的版本號對不上 | workflow 先檢查，不一樣就停 | `.github/workflows/publish.yml` |
| 服務帳戶金鑰是 `.json` | 不小心 commit 就外洩 | `.gitignore` 擋掉所有 `.json`（manifest 除外） | `.gitignore` |
| public repo 的 commit 作者 email | 會公開 | 這個 repo 用 GitHub noreply email | `git config user.email` |
| 截圖拍到網址列、書籤列、真的網址、帳號 | 上架後公開；放在 repo 裡可能被 `git add -A` 推上 GitHub | 只框網頁內容；原始截圖放 `raw-screenshots/`（git 不追蹤） | `.gitignore`、[上架與自動發布.md](上架與自動發布.md)「截圖注意」 |
| popup 截圖會帶到帳號名稱 | 商店截圖公開 | 蓋掉帳號那段；原圖留在 `raw-screenshots/popup.png`，蓋好的是 `popup-clean.png` | `raw-screenshots/`（不進 git） |
| 文件範例檔名 `截圖.png` 被照打 | `FileNotFoundError` | 文件改成 `<你的檔名>`；找不到檔案時印出白話提示 | `scripts/fit_screenshot.py` |

## 六、問答

| 問題 | 答案 | 依據 |
| --- | --- | --- |
| 為什麼原本寫死 StudyDeck 網址？ | 只當設定頁的預設值，第一次不用自己打。所有 API 都用設定裡的網址，跟預設值無關。上架會公開，所以拿掉 | `src/settings.js:3` |
| extension 有自己的資料庫嗎？ | 沒有。單字存在 StudyDeck；extension 只在瀏覽器存 3 樣：網址、登入憑證、帳號名稱。密碼不存 | `src/settings.js:4` |
| 沒註冊什麼金鑰，怎麼連得到 StudyDeck？ | 跟網站登入一樣：用帳密換一張登入憑證，之後每次呼叫都帶 `Authorization: Bearer <憑證>`。StudyDeck 本來就認這種憑證 | `src/api.js:21`、`quizlet/backend/src/lib/auth.js:21` |
| 那 Google 服務帳戶金鑰是做什麼的？ | 只用來「上傳新版到商店」，跟連 StudyDeck 無關；只存在 GitHub secret | `scripts/publish.mjs` |
| 為什麼一定要隱私權政策？ | 選的字、句子、帳密會經過 extension 送到伺服器，商店規定處理使用者資料要附政策 | `PRIVACY.md` |
